# 需求规格说明书

## 1. 项目概述

### 1.1 项目名称
ROS话题发布订阅Demo程序

### 1.2 项目简介
一个简单的ROS1 C++ demo程序，演示话题发布和订阅的基本功能。程序包含一个节点同时作为发布者和订阅者，实现消息的自循环测试。

### 1.3 目标用户
- ROS初学者
- 需要快速验证ROS环境配置的开发者
- 学习ROS话题通信机制的用户

## 2. 功能需求

### 2.1 核心功能

#### 功能点 1：话题发布功能
- 描述：创建一个发布者节点，定期向指定话题发布字符串消息
- 优先级：高
- 前置条件：ROS环境已正确配置，roscore已启动
- 操作流程：
  1. 初始化ROS节点
  2. 创建发布者对象
  3. 设置定时器，定期发布消息
  4. 发布包含时间戳的"Hello ROS!"消息
- 预期结果：消息成功发布到指定话题

#### 功能点 2：话题订阅功能
- 描述：创建一个订阅者节点，监听指定话题的消息
- 优先级：高
- 前置条件：话题上有消息发布
- 操作流程：
  1. 初始化ROS节点
  2. 创建订阅者对象
  3. 设置回调函数处理接收到的消息
  4. 在控制台打印接收到的消息内容
- 预期结果：成功接收并处理发布的消息

#### 功能点 3：自循环测试
- 描述：同一个节点既发布消息又订阅同一话题
- 优先级：中
- 前置条件：发布者和订阅者功能正常工作
- 操作流程：
  1. 节点启动后开始发布消息
  2. 同时订阅同一话题
  3. 验证是否能收到自己发布的消息
- 预期结果：节点能收到自己发布的消息，实现自循环测试

### 2.2 用户交互

#### 用户角色
| 角色 | 描述 | 权限 |
|------|------|------|
| 开发者 | 运行和测试程序 | 启动/停止节点，查看日志输出 |

#### 界面原型（文字描述）
- 命令行界面：通过终端启动节点
- 控制台输出：显示发布的消息内容和接收到的消息内容
- ROS工具：可使用`rostopic echo`和`rostopic list`验证话题通信

## 3. 数据需求

### 3.1 数据实体

| 实体名称 | 说明 | 主要属性 |
|----------|------|----------|
| ROS消息 | 话题通信的数据载体 | data（字符串内容），header（时间戳） |
| 话题 | 消息传输的通道 | name（话题名称），message_type（消息类型） |

### 3.2 数据操作

| 操作 | 输入 | 输出 | 约束 |
|------|------|------|------|
| 发布消息 | 字符串消息 | 无 | 消息格式必须符合std_msgs/String |
| 订阅消息 | 无 | 字符串消息 | 回调函数必须正确处理消息 |
| 消息处理 | ROS消息对象 | 控制台输出 | 提取消息内容并格式化输出 |

## 4. 非功能需求

### 4.1 性能需求
- 响应时间：消息发布到接收延迟 < 100ms
- 并发能力：支持单节点运行
- 吞吐量：1条消息/秒

### 4.2 安全需求
- 认证方式：ROS内置节点认证
- 权限控制：无特殊权限要求
- 数据保护：消息内容为公开测试数据

### 4.3 部署需求
- 运行环境：Ubuntu + ROS1（Noetic/Melodic）
- 依赖服务：roscore核心服务
- 编译系统：catkin构建系统

## 5. 验收标准

### 5.1 功能验收
- [ ] 节点能成功启动并连接到roscore
- [ ] 发布者能定期发布消息到`/chat`话题
- [ ] 订阅者能接收到发布的消息
- [ ] 控制台能正确显示发布和接收的消息内容
- [ ] 使用`rostopic echo /chat`能验证消息传输

### 5.2 质量标准
- 代码编译无错误
- 节点启动时间 < 5秒
- 消息发布间隔稳定在1秒±100ms
- 代码符合ROS C++编程规范
