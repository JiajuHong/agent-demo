# 需求规格说明书

## 1. 项目概述

### 1.1 项目名称
ROS话题发布订阅Demo程序

### 1.2 项目简介
一个简单的ROS1话题发布订阅演示程序，包含一个发布者节点和一个订阅者节点，用于演示ROS话题通信的基本机制。

### 1.3 目标用户
- ROS初学者，学习ROS话题通信机制
- 开发者需要快速验证ROS环境配置
- 教学演示用途

## 2. 功能需求

### 2.1 核心功能

#### 功能点 1：话题发布者
- 描述：创建一个ROS节点，定期向指定话题发布消息
- 优先级：高
- 前置条件：ROS环境已正确配置和启动
- 操作流程：
  1. 初始化ROS节点
  2. 创建话题发布者
  3. 设置发布频率（1Hz）
  4. 循环发布消息
- 预期结果：消息成功发布到指定话题

#### 功能点 2：话题订阅者
- 描述：创建一个ROS节点，订阅指定话题并接收消息
- 优先级：高
- 前置条件：ROS环境已正确配置和启动，发布者节点正在运行
- 操作流程：
  1. 初始化ROS节点
  2. 创建话题订阅者
  3. 设置消息回调函数
  4. 进入ROS循环等待消息
- 预期结果：成功接收并处理发布者发送的消息

#### 功能点 3：消息处理
- 描述：订阅者节点接收消息后进行处理和显示
- 优先级：中
- 前置条件：订阅者节点已成功订阅话题
- 操作流程：
  1. 定义消息回调函数
  2. 在回调函数中提取消息内容
  3. 将消息内容打印到控制台
- 预期结果：在控制台显示接收到的消息内容

### 2.2 用户交互

#### 用户角色
| 角色 | 描述 | 权限 |
|------|------|------|
| 系统管理员 | 负责启动和监控ROS系统 | 启动roscore，运行节点 |
| 开发者 | 使用demo程序进行测试和学习 | 编译、运行、调试程序 |

#### 界面原型（文字描述）
- 控制台界面：通过终端运行程序，在控制台输出日志信息
- 消息显示：订阅者节点在控制台打印接收到的消息内容
- 状态指示：发布者节点显示发布计数和状态

## 3. 数据需求

### 3.1 数据实体

| 实体名称 | 说明 | 主要属性 |
|----------|------|----------|
| ROS消息 | 话题通信的数据载体 | data（字符串内容） |
| 话题 | 消息传输的通道 | name（话题名称） |
| 节点 | ROS系统中的执行单元 | name（节点名称） |

### 3.2 数据操作

| 操作 | 输入 | 输出 | 约束 |
|------|------|------|------|
| 发布消息 | 字符串消息 | 无 | 消息格式符合std_msgs/String |
| 订阅消息 | 无 | 字符串消息 | 需要话题名称匹配 |
| 处理消息 | 原始消息 | 格式化输出 | 需要消息解析 |

## 4. 非功能需求

### 4.1 性能需求
- 响应时间：消息发布到接收延迟 < 100ms
- 并发能力：支持单发布者单订阅者模式
- 吞吐量：1条消息/秒

### 4.2 安全需求
- 认证方式：ROS内置节点认证
- 权限控制：无特殊权限要求
- 数据保护：无敏感数据，无需加密

### 4.3 部署需求
- 运行环境：Ubuntu Linux + ROS Noetic/Melodic
- 依赖服务：roscore主节点
- 构建工具：CMake + catkin_make

## 5. 验收标准

### 5.1 功能验收
- [ ] 发布者节点可正常启动并发布消息
- [ ] 订阅者节点可正常启动并接收消息
- [ ] 消息内容正确传递和显示
- [ ] 两个节点可独立运行和停止

### 5.2 质量标准
- 代码编译无错误
- ROS节点注册和注销正常
- 内存管理正确，无内存泄漏
- 代码注释清晰，符合ROS编程规范
