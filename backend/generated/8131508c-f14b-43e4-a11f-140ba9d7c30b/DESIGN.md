# 软件设计文档

## 1. 系统架构

### 1.1 整体架构

**架构说明**：这是一个简单的控制台五子棋游戏，采用单文件架构，所有功能模块都在一个Python文件中实现。游戏采用面向过程的设计，通过函数模块化组织代码。

**技术栈**：
- 编程语言：Python 3.6+
- 界面：控制台字符界面
- 依赖：无外部依赖，仅使用Python标准库

**架构图**：
```mermaid
flowchart TD
    A[玩家输入] --> B[主控制循环]
    B --> C{游戏状态判断}
    C -->|进行中| D[显示棋盘]
    D --> E[获取玩家输入]
    E --> F[验证并落子]
    F --> G[检查胜负]
    G --> C
    C -->|游戏结束| H[显示结果]
    H --> I[询问重新开始]
    I -->|是| B
    I -->|否| J[退出游戏]
```

### 1.2 模块划分

| 模块名称 | 职责 | 依赖模块 |
|---------|------|----------|
| 棋盘管理 | 初始化、显示、更新棋盘状态 | 无 |
| 输入处理 | 解析玩家输入的坐标，验证有效性 | 棋盘管理 |
| 游戏逻辑 | 落子、胜负判断、游戏状态管理 | 棋盘管理 |
| 主程序 | 控制游戏流程，协调各模块 | 所有模块 |

### 1.3 项目目录结构

```
gomoku/
└── gomoku.py    # 主程序文件，包含所有功能
```

## 2. API 设计

### 2.1 数据表示

**棋盘状态**：
- 使用15x15的二维列表表示棋盘
- 每个位置的值：0（空）、1（黑棋）、2（白棋）

**坐标系统**：
- 内部：使用(0-14, 0-14)的整数坐标
- 外部：使用"A1"到"O15"的字母+数字格式

### 2.2 核心函数接口

#### 2.2.1 棋盘管理模块

**函数名称**：`init_board()`

功能：初始化空棋盘

返回值：
```python
[[0 for _ in range(15)] for _ in range(15)]
```

**函数名称**：`print_board(board)`

功能：在控制台显示棋盘

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| board | list | 是 | 15x15的棋盘状态 |

**函数名称**：`place_stone(board, row, col, player)`

功能：在指定位置放置棋子

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| board | list | 是 | 棋盘状态 |
| row | int | 是 | 行坐标(0-14) |
| col | int | 是 | 列坐标(0-14) |
| player | int | 是 | 玩家(1:黑棋, 2:白棋) |

返回值：更新后的棋盘

#### 2.2.2 输入处理模块

**函数名称**：`parse_input(input_str)`

功能：解析玩家输入的坐标

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| input_str | str | 是 | 玩家输入的坐标字符串 |

返回值：(row, col) 或 None（如果输入无效）

**函数名称**：`is_valid_move(board, row, col)`

功能：验证落子位置是否有效

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| board | list | 是 | 棋盘状态 |
| row | int | 是 | 行坐标 |
| col | int | 是 | 列坐标 |

返回值：bool（True表示有效）

#### 2.2.3 游戏逻辑模块

**函数名称**：`check_win(board, row, col, player)`

功能：检查指定位置落子后是否获胜

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| board | list | 是 | 棋盘状态 |
| row | int | 是 | 行坐标 |
| col | int | 是 | 列坐标 |
| player | int | 是 | 玩家(1:黑棋, 2:白棋) |

返回值：bool（True表示获胜）

**函数名称**：`check_direction(board, row, col, dx, dy, player)`

功能：检查指定方向上的连续棋子数

参数：
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| board | list | 是 | 棋盘状态 |
| row | int | 是 | 起始行坐标 |
| col | int | 是 | 起始列坐标 |
| dx | int | 是 | 行方向增量(-1,0,1) |
| dy | int | 是 | 列方向增量(-1,0,1) |
| player | int | 是 | 玩家(1:黑棋, 2:白棋) |

返回值：int（连续棋子数）

## 3. 数据库设计

## 4. 核心模块设计

### 4.1 棋盘管理模块

**职责**：管理棋盘状态的初始化、显示和更新

**核心函数**：
- `init_board()`: 创建空棋盘
- `print_board(board)`: 显示棋盘
- `place_stone(board, row, col, player)`: 放置棋子

**流程图**：
```mermaid
flowchart TD
    A[开始显示棋盘] --> B[打印列标题A-O]
    B --> C[遍历每一行]
    C --> D[打印行号]
    D --> E[遍历每一列]
    E --> F{判断格子状态}
    F -->|空| G[打印.]
    F -->|黑棋| H[打印●]
    F -->|白棋| I[打印○]
    G --> J[继续下一列]
    H --> J
    I --> J
    J --> K{是否最后一列}
    K -->|否| E
    K -->|是| L[换行]
    L --> M{是否最后一行}
    M -->|否| C
    M -->|是| N[显示当前玩家]
    N --> O[结束]
```

### 4.2 游戏逻辑模块

**职责**：实现游戏规则，包括胜负判断

**核心算法**：胜负判断算法

```mermaid
flowchart TD
    A[开始检查胜负] --> B[定义四个检查方向]
    B --> C[方向1: 水平 dx=0, dy=1]
    B --> D[方向2: 垂直 dx=1, dy=0]
    B --> E[方向3: 左上右下 dx=1, dy=1]
    B --> F[方向4: 右上左下 dx=1, dy=-1]
    
    C --> G[检查方向连续棋子]
    D --> G
    E --> G
    F --> G
    
    G --> H[计算正反方向连续数]
    H --> I[总连续数 = 正方向 + 反方向 - 1]
    I --> J{总连续数 >= 5}
    J -->|是| K[返回True]
    J -->|否| L[检查下一个方向]
    L --> M{所有方向检查完毕}
    M -->|否| G
    M -->|是| N[返回False]
```

### 4.3 主程序模块

**职责**：控制游戏主循环和流程

**主循环流程图**：
```mermaid
flowchart TD
    A[游戏开始] --> B[初始化棋盘和状态]
    B --> C[显示棋盘]
    C --> D[提示当前玩家输入]
    D --> E[获取玩家输入]
    E --> F{输入是否有效}
    F -->|否| G[显示错误信息]
    G --> D
    F -->|是| H[在棋盘落子]
    H --> I[检查是否获胜]
    I -->|是| J[显示获胜信息]
    I -->|否| K[切换玩家]
    K --> C
    J --> L[询问是否重新开始]
    L -->|是| B
    L -->|否| M[游戏结束]
```

## 5. 错误处理设计

### 5.1 输入验证错误
- 坐标格式错误（如"AA1"、"1A"等）
- 坐标超出范围（如"P1"、"A16"等）
- 位置已有棋子

### 5.2 处理策略
- 提供清晰的错误提示信息
- 允许玩家重新输入
- 不中断游戏流程
