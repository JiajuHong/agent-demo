# 需求规格说明书

## 1. 项目概述

### 1.1 项目名称
ROS话题发布订阅Demo程序

### 1.2 项目简介
一个简单的ROS1（Noetic）C++程序，演示话题发布者和订阅者的基本用法。包含两个节点：一个发布者节点定期发布消息，一个订阅者节点接收并显示消息。

### 1.3 目标用户
- ROS初学者
- 需要快速了解ROS话题通信机制的开发者
- 教学演示用途

## 2. 功能需求

### 2.1 核心功能

#### 功能点 1：发布者节点
- 描述：创建一个发布者节点，定期向指定话题发布消息
- 优先级：高
- 前置条件：ROS环境已安装并配置
- 操作流程：
  1. 初始化ROS节点
  2. 创建话题发布者
  3. 设置发布频率（如1Hz）
  4. 循环发布消息
- 预期结果：消息成功发布到指定话题

#### 功能点 2：订阅者节点
- 描述：创建一个订阅者节点，订阅指定话题并接收消息
- 优先级：高
- 前置条件：发布者节点正在运行
- 操作流程：
  1. 初始化ROS节点
  2. 创建话题订阅者
  3. 设置回调函数处理接收到的消息
  4. 保持运行等待消息
- 预期结果：成功接收并显示发布者发送的消息

#### 功能点 3：自定义消息类型
- 描述：使用自定义消息类型进行通信
- 优先级：中
- 前置条件：ROS包已创建
- 操作流程：
  1. 定义自定义消息格式
  2. 在CMakeLists.txt和package.xml中配置
  3. 在代码中使用自定义消息
- 预期结果：发布者和订阅者使用自定义消息类型通信

### 2.2 用户交互

#### 用户角色
| 角色 | 描述 | 权限 |
|------|------|------|
| 开发者 | 运行和测试程序 | 编译、运行、调试程序 |

#### 界面原型（文字描述）
- 终端界面：通过命令行启动节点，在终端查看输出
- 发布者输出：显示发布的消息内容和时间戳
- 订阅者输出：显示接收到的消息内容和时间戳

## 3. 数据需求

### 3.1 数据实体

| 实体名称 | 说明 | 主要属性 |
|----------|------|----------|
| DemoMessage | 自定义消息类型 | id, content, timestamp |
| PublisherNode | 发布者节点 | node_name, topic_name, publish_rate |
| SubscriberNode | 订阅者节点 | node_name, topic_name, callback_function |

### 3.2 数据操作

| 操作 | 输入 | 输出 | 约束 |
|------|------|------|------|
| 发布消息 | DemoMessage对象 | 无 | 发布频率不超过10Hz |
| 订阅消息 | 话题名称 | DemoMessage对象 | 话题必须存在 |
| 处理消息 | DemoMessage对象 | 控制台输出 | 实时处理 |

## 4. 非功能需求

### 4.1 性能需求
- 响应时间：消息延迟 < 100ms
- 并发能力：支持多个订阅者同时订阅
- 吞吐量：支持10Hz的发布频率

### 4.2 安全需求
- 认证方式：ROS内置节点认证
- 权限控制：无特殊权限要求
- 数据保护：消息内容明文传输

### 4.3 部署需求
- 运行环境：Ubuntu 20.04 + ROS Noetic
- 依赖服务：roscore（ROS主节点）
- 构建工具：catkin_make

## 5. 验收标准

### 5.1 功能验收
- [ ] 发布者节点可正常启动并发布消息
- [ ] 订阅者节点可正常启动并接收消息
- [ ] 消息内容正确传递
- [ ] 可同时运行多个订阅者

### 5.2 质量标准
- 代码编译无错误
- 节点启动时间 < 2秒
- 消息传递成功率 > 99%
- 代码注释覆盖率 > 50%
